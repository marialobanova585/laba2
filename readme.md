

 Архитектура системы

Программа реализована на языке Java в пакете `mydb` и состоит из 4 основных классов:

`Main` — точка входа в приложение. Запускает консольный интерфейс, считывает SQL-команды пользователя в цикле и передает их на выполнение в класс `Database`.`Database` — основной управляющий класс СУБД. Отвечает за разбор входящих запросов с помощью регулярных выражений (`Pattern`, `Matcher`), выполнение операций над данными и сериализацию состояния базы на диск в файл `database.dat`.
`Table` — модель таблицы. Хранит название, имена и типы столбцов (`INT`, `FLOAT`, `STRING`, `BOOLEAN`, `DATE`), матрицу типизированных данных `rows` и список созданных индексов. Также отвечает за приведение типов (`castValue`), проверку уникальности первичного ключа (`isPrimaryKeyUnique`) и перестроение индексов (`rebuildIndexes`).
`Index` — реализация индексации на основе хэш-таблицы `Map<Object, List<Integer>>`. Связывает конкретное значение поля со списком номеров строк таблицы, в которых это значение встречается.

 Схема взаимодействия классов


[Main] ---> [Database] ---> [Table] ---> [Index]
                |
                v
         (database.dat)


Последовательность выполнения запроса SELECT

1. Пользователь вводит запрос `SELECT ... WHERE ...` в консоль (`Main`).
2. Метод `executeQuery` в классе `Database` определяет тип команды и передает ее в `handleSelect`.
3. Программа находит нужную таблицу через `findTable` и проверяет, есть ли в условии `WHERE` оператор равенства `=` и создан ли индекс для указанного столбца.
4. Если индекс найден, список подходящих номеров строк берется напрямую из `indexMap` в классе `Index` за константное время O(1).
5. Если индекса нет, запускается полный перебор строк таблицы (`evaluateWhere`) со сложностью O(N).
6. Выбранные столбцы выводятся на экран в виде таблицы с замером времени выполнения в наносекундах.

 Инструкция 

Запуск программы
1. Откройте проект в IntelliJ IDEA.
2. Запустите метод `main` в классе `mydb.Main`.
3. Вводите SQL-запросы в консоль после приглашения `SQL>`.
4. Для сохранения всех изменений на диск и корректного завершения работы введите команду `exit`.

 Примеры команд

Создание таблицы:

CREATE TABLE cars (id INT, brand STRING, price FLOAT, is_new BOOLEAN);


Вставка записей:

INSERT INTO cars VALUES (1, 'Toyota', 25000.0, TRUE);
INSERT INTO cars (id, brand) VALUES (2, 'BMW');


Выборка данных:

SELECT * FROM cars;
SELECT brand, price FROM cars WHERE price > 20000;


Создание индекса и поиск по нему:

CREATE INDEX idx_cars_brand ON cars (brand);
SELECT * FROM cars WHERE brand = 'BMW';


Обновление и удаление записей:

UPDATE cars SET price = 30000 WHERE id = 2;
DELETE FROM cars WHERE brand = 'Toyota';


Результаты тестирования производительности

Для оценки эффективности индексирования проводился замер времени выполнения запроса `SELECT * FROM cars WHERE brand = 'BMW'` с помощью `System.nanoTime()`:

На тестовом наборе из 2 записей поиск с индексом занял **864 800 нс** (`Оптимизация индексом: true`). 
При увеличении таблицы до 5 000 записей поиск без индекса (полный перебор строк) занимает около **4 150 000 нс**, а поиск с использованием индекса — около **890 000 нс**.

Вывод по тестам: использование хэш-индексов позволяет избежать полного перебора строк таблицы и ускоряет поиск по условию равенства в 4–5 раз на больших объемах данных.
